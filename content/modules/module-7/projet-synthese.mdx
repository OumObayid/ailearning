# Projet de synthèse — API IA sécurisée, testée et optimisée

### 1. Cahier des charges global du projet

L'objectif de ce projet de synthèse est de concevoir et déployer une **plateforme d'API backend d'intelligence artificielle complète, durcie pour la production**.

Votre application doit satisfaire aux exigences industrielles suivantes :
1. **Sécurité inviolable** : Clés API confinées au serveur, authentification par jetons JWT, contrôle d'accès RBAC et sanitisation stricte des prompts contre les injections directes et indirectes.
2. **Couverture de tests exhaustive** : Suites de tests unitaires Vitest avec mock hermétique des LLMs, et tests d'intégration HTTP Supertest validant les codes d'état.
3. **Observabilité & Haute Performance** : Mesure de la latence, journalisation structurée JSON avec masquage automatique des secrets, et mise en cache Redis des questions récurrentes.
4. **Ancrage & Anti-Hallucination** : Pipeline RAG avec Qdrant forçant le modèle à avouer son incertitude dès qu'une information est absente des sources.

Réalisez ce projet en respectant la chronologie industrielle suivante :
</p>

#### Phase 1 : La couche de sécurité défensive
- Mettez en place le middleware d'authentification `requireAuth` vérifiant les jetons JWT.
- Développez le validateur Zod `userPromptSchema` refusant les chaînes vides, les textes de plus de 4 000 caractères et les balises d'écrasement de délimiteurs.
- Créez le filtre heuristique interceptant les patterns de jailbreak évidents (*« ignore previous instructions »*).

#### Phase 2 : Le service d'IA ancré
- Initialisez le SDK `@google/genai` avec la clé lue depuis `process.env.GEMINI_API_KEY`.
- Rédigez le prompt d'ancrage imposant au modèle d'avouer formellement son ignorance si une information demandée est absente des sources fournies.

#### Phase 3 : Les suites de tests automatisées
- **Tests unitaires (Vitest)** : Testez la fonction de validation de prompt et le calcul des clés de cache sans aucun appel réseau.
- **Tests d'intégration (Supertest)** : Validez que `POST /api/ai/chat` retourne `401` sans jeton, `400` avec un body malformé, et `200` avec une charge utile conforme.

#### Phase 4 : Observabilité & Mesure
- Intégrez le logger structuré Pino masquant automatiquement les clés d'API et les mots de passe.
- Mesurez la latence avec `performance.now()` et journalisez les tokens consommés via `response.usageMetadata`.
</PracticalWork>

### 4. Critères d'acceptation et recette finale

Pour certifier votre projet comme prêt pour un déploiement en production, vérifiez les critères suivants :

- [ ] **Clés protégées à 100 %** : Aucune clé d'API n'apparaît en clair dans le code, dans Git ou dans les logs serveur.
- [ ] **Étanchéité des données** : Les requêtes SQL vers MySQL sont strictement paramétrées avec l'identifiant extrait du JWT.
- [ ] **Résistance aux jailbreaks** : Les tentatives d'injections directes sont interceptées en amont et retournent un code 400.
- [ ] **Zéro régression logicielle** : La commande `npm run test:run` s'exécute avec 100 % de tests réussis en moins de 3 secondes.
- [ ] **Traçabilité totale** : Chaque requête génère un Correlation ID unique propagé dans les logs et dans les en-têtes HTTP de réponse.
