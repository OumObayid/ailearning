# Chapitre 15 — Logs structurés, traçabilité et observabilité avec OpenTelemetry

### 1. Logs vs Observabilité : Les 3 piliers

On confond fréquemment la simple **journalisation (*Logs*)** avec l'**observabilité complète** d'un système informatique :
- **Les Logs** : Événements textuels ponctuels horodatés décrivant ce qui s'est produit à un instant $T$.
- **Les Métriques** : Valeurs numériques agrégées dans le temps (taux d'erreur 500, consommation de tokens par minute, temps de réponse P95).
- **Les Traces distribuées** : Le parcours exhaustif d'une requête traversant le frontend React, l'API Express, la recherche Qdrant, la requête MySQL et l'appel externe Google Gemini.

### 2. Journalisation structurée avec Pino et règles d'exclusion

Les commandes classiques `console.log("Erreur:", err)` sont proscrites en production : elles ne sont ni indexables par les collecteurs de logs (Datadog, ElasticSearch, CloudWatch), ni protégées contre les fuites de données.

Utilisez une bibliothèque de journalisation structurée au format JSON comme **Pino** :

### 3. Traçabilité distribuée avec Correlation IDs (Trace IDs)

Lorsqu'un utilisateur subit une erreur, comment retrouver en quelques secondes le log précis parmi des millions de lignes ?
La solution réside dans l'attribution d'un **Correlation ID (ou Trace ID)** unique généré dès la passerelle Express et propagé à chaque sous-composant :

<ArchitectureDiagram
  title="Propagation du Correlation ID à travers toute la chaîne"
  diagram={`NAVIGATEUR (X-Correlation-ID: req_89f1a04b)
        |
        v
MIDDLEWARE EXPRESS (Injecte req.correlationId)
        |
        +---> LOG 1 : "Réception requête chat" [ID: req_89f1a04b]
        |
        +---> APPEL QDRANT (Embedding + Recherche) [ID: req_89f1a04b]
        |
        +---> REQUÊTE MYSQL (Historique) [ID: req_89f1a04b]
        |
        +---> APPEL GOOGLE GEMINI [ID: req_89f1a04b]
        |
        v
RÉPONSE HTTP RETOURNÉE (X-Correlation-ID: req_89f1a04b)`}
/>

<CodeBlock
  language="typescript"
  title="src/middlewares/correlation.middleware.ts — Middleware de corrélation"
  code={`import { Request, Response, NextFunction } from 'express';
import { randomUUID } from 'crypto';

export function correlationMiddleware(req: Request, res: Response, next: NextFunction) {
  const correlationId = (req.headers['x-correlation-id'] as string) || \`req_\${randomUUID()}\`;
  
  // Attachement au contexte et propagation dans l'en-tête de réponse
  res.locals.correlationId = correlationId;
  res.setHeader('X-Correlation-ID', correlationId);

  next();
}`}
/>
