# Chapitre 2 — Authentification JWT, autorisations RBAC et contrôle d'accès aux données

### 1. Authentification vs Autorisation : Principes fondamentaux

Dans la sécurisation d'une plateforme d'intelligence artificielle, deux concepts distincts mais complémentaires interviennent :

- **L'authentification (Qui êtes-vous ?)** : Elle valide formellement l'identité du demandeur à l'aide d'un mot de passe, d'un jeton signé cryptographiquement (**JWT**) ou d'un fournisseur OAuth2.
- **L'autorisation (Que pouvez-vous faire ?)** : Elle détermine les privilèges exacts accordés à cette identité (**RBAC - Role-Based Access Control**).

| Rôle | Capacité autorisée sur l'API IA | Actions interdites |
| :--- | :--- | :--- |
| **Visiteur (Public)** | Poser des questions générales sur la documentation publique | Consulter l'historique ou exécuter des outils |
| **Utilisateur standard** | Dialoguer avec son assistant privé, interroger ses propres commandes | Accéder aux commandes d'autres utilisateurs ou modifier des statuts |
| **Opérateur Support** | Rechercher dans les tickets et consulter les logs techniques | Rembourser des montants élevés sans validation supérieure |
| **Administrateur** | Gérer les comptes, auditer les métriques, reconfigurer les agents | — |

### 2. Middleware Express d'authentification par jeton JWT

Voici l'implémentation d'un middleware TypeScript robuste qui intercepte l'en-tête `Authorization: Bearer <TOKEN>`, vérifie sa signature et attache le profil de l'utilisateur à `res.locals` :

<CodeBlock
  language="typescript"
  title="src/middlewares/auth.middleware.ts — Validation JWT"
  code={`import { Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

export interface AuthenticatedUserPayload {
  userId: number;
  email: string;
  role: 'user' | 'support' | 'admin';
  permissions: string[];
}

const JWT_SECRET = process.env.JWT_SECRET || 'fallback_secret_for_dev_only';

export function requireAuth(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;

  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({
      success: false,
      error: "Accès refusé : Jeton d'authentification Bearer manquant ou malformé.",
    });
  }

  const token = authHeader.substring(7);

  try {
    const decoded = jwt.verify(token, JWT_SECRET) as AuthenticatedUserPayload;
    res.locals.user = decoded; // Identité vérifiée et hermétique
    next();
  } catch (err: any) {
    return res.status(401).json({
      success: false,
      error: "Session invalide ou expirée. Veuillez vous reconnecter.",
    });
  }
}`}
/>

### 3. Sécurisation des routes d'inférence IA

Chaque point d'entrée sollicitant Gemini doit être protégé par le middleware d'authentification :

<CodeBlock
  language="typescript"
  title="src/routes/ai.routes.ts — Route protégée avec contrôle RBAC"
  code={`import { Router, Request, Response } from 'express';
import { requireAuth } from '../middlewares/auth.middleware';
import { ai } from '../config/gemini';

export const aiRouter = Router();

aiRouter.post('/chat', requireAuth, async (req: Request, res: Response) => {
  const user = res.locals.user;
  const { prompt } = req.body;

  // L'identité provient exclusivement du jeton vérifié, jamais du body client
  console.log(\`Requête IA initiée par l'utilisateur #\${user.userId} (\${user.email})\`);

  try {
    const response = await ai.models.generateContent({
      model: 'gemini-2.5-flash',
      contents: prompt,
    });

    return res.json({
      success: true,
      text: response.text,
      userId: user.userId,
    });
  } catch (error: any) {
    return res.status(500).json({ error: error.message });
  }
});`}
/>

### 4. Contrôle d'accès SQL strict : Cloisonnement des données par user_id

Dans une application IA connectée à une base de données (comme MySQL ou Qdrant), **vous ne devez JAMAIS vous reposer sur le bon vouloir de Gemini pour empêcher un utilisateur de voir les documents d'un tiers**.

<Callout type="danger" title="ANTI-PATTERN CRITIQUE (Vulnérabilité IDOR)">
Ne demandez jamais à Gemini : <em>« Affiche les commandes de l&apos;utilisateur 12 si l&apos;utilisateur actuel a le droit »</em>.
<br />
Le filtrage par identifiant doit être <strong>garanti de façon inconditionnelle par le code SQL de votre serveur</strong> :
</Callout>

<CodeBlock
  language="typescript"
  title="src/services/order.service.ts — Isolation stricte au niveau de la requête SQL"
  code={`import { pool } from '../config/database';

export async function getAuthenticatedUserOrders(userId: number, orderId: number) {
  // La clause WHERE intègre obligatoirement user_id pour cloisonner les données
  const [rows]: any = await pool.execute(
    \`SELECT id, total_amount, status, created_at
     FROM orders
     WHERE id = ? AND user_id = ?\`,
    [orderId, userId]
  );

  if (rows.length === 0) {
    throw new Error("Commande introuvable ou vous n'êtes pas autorisé à y accéder.");
  }

  return rows[0];
}`}
