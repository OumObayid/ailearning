# Chapitre 5 — Architecture backend Express en couches et contrats d'API REST

### 1. Organisation en couches industrielles

Pour maintenir une base de code de grande envergure, le code backend est découpé selon le patron de conception en couches (**Layered Architecture**) :

  title="Flux de traitement à travers les couches backend"

### 2. Spécification détaillée des endpoints de l'API REST

Le contrat d'API de la plateforme s'articule autour des points de terminaison normalisés suivants :

| Méthode | Route HTTP | Description & Rôle | Autorisation minimale |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/login` | Authentification utilisateur & génération du token JWT | Public |
| `GET` | `/api/auth/me` | Récupération du profil de l'utilisateur connecté | Authentifié |
| `POST` | `/api/documents/upload` | Téléversement d'un document PDF pour ingestion RAG | Rôle `manager` ou `collaborator` |
| `GET` | `/api/documents` | Liste paginée des documents autorisés pour l'utilisateur | Authentifié |
| `DELETE` | `/api/documents/:id` | Suppression d'un document et de ses vecteurs Qdrant | Propriétaire ou `admin` |
| `POST` | `/api/conversations` | Création d'une nouvelle session de dialogue RAG | Authentifié |
| `POST` | `/api/conversations/:id/messages` | Envoi d'une question avec réponse streamée et sources | Authentifié |
| `POST` | `/api/agents/run` | Déclenchement d'une tâche d'agent autonome multi-outils | Rôle `manager` |
| `POST` | `/api/automations/:workflow` | Déclenchement d'un workflow d'automatisation n8n | Authentifié |

### 3. Standardisation des formats de réponses JSON et gestion d'erreurs

Toutes les réponses de l'API respectent un contrat d'enveloppe uniforme, facilitant la consommation par le client React :

<CodeBlock
  language="typescript"
  title="src/types/apiResponse.ts — Enveloppe standardisée"
  code={`export interface ApiResponse<T = unknown> {
  success: boolean;
  data?: T;
  error?: {
    code: string;
    message: string;
    details?: unknown;
  };
  meta?: {
    timestamp: string;
    correlationId: string;
  };
}`}
/>

Un middleware d'erreur centralisé intercepte toute exception inattendue pour éviter de faire planter le processus Node.js :

<CodeBlock
  language="typescript"
  title="src/middlewares/errorHandler.ts — Gestionnaire centralisé d'exceptions"
  code={`import { Request, Response, NextFunction } from 'express';
import { logger } from '../utils/logger';

export function centralErrorHandler(
  err: any,
  req: Request,
  res: Response,
  next: NextFunction
) {
  const correlationId = res.locals.correlationId || 'unknown_req';
  const statusCode = err.statusCode || 500;

  logger.error({
    event: 'api_error_intercepted',
    correlationId,
    statusCode,
    message: err.message,
    stack: process.env.NODE_ENV === 'development' ? err.stack : undefined,
  });

  return res.status(statusCode).json({
    success: false,
    error: {
      code: err.code || 'INTERNAL_SERVER_ERROR',
      message: err.message || "Une erreur interne est survenue.",
    },
    meta: {
      timestamp: new Date().toISOString(),
      correlationId,
    },
  });
}`}
/>
