# Chapitre 11 — Intégration de n8n par Webhooks sécurisés et workflows asynchrones

### 1. Architecture de couplage entre Express et n8n

Dans notre plateforme, le serveur Node.js délègue les tâches d'arrière-plan complexes (envoi de notifications Slack/Email, génération de rapports PDF, synchronisation avec des CRMs tiers) à une instance dédiée de **n8n**.

Ce découplage apporte des avantages fondamentaux :
- **Soulagement de la boucle d'événements Node.js** : Les opérations d'E/S lentes ne bloquent pas l'API principale.
- **Observabilité visuelle des workflows** : Les équipes opérationnelles peuvent auditer les exécutions et réparer un flux sans modifier le code source TypeScript de l'API.
- **Gestion intégrée des retries** : Si un serveur SMTP distant subit une défaillance transitoire, n8n gère la reprise automatique avec temporisation exponentielle.

### 2. Sécurisation des webhooks par header X-Webhook-Secret

Pour empêcher que des tiers n'appellent arbitrairement les points d'entrée de vos flux n8n, chaque requête émise depuis Express transporte un secret partagé :

<CodeBlock
  language="typescript"
  title="src/modules/automations/n8nClient.service.ts — Appel webhook sécurisé"
  code={`export async function triggerN8nWorkflow(workflowPath: string, payload: Record<string, unknown>) {
  const baseUrl = process.env.N8N_BASE_URL || 'http://localhost:5678';
  const secret = process.env.N8N_WEBHOOK_SECRET;

  if (!secret) {
    throw new Error("N8N_WEBHOOK_SECRET non configuré dans le backend.");
  }

  const endpoint = \`\${baseUrl}/webhook/\${workflowPath}\`;

  const response = await fetch(endpoint, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Webhook-Secret': secret,
    },
    body: JSON.stringify({
      ...payload,
      triggeredAt: new Date().toISOString(),
    }),
  });

  if (!response.ok) {
    throw new Error(\`Erreur lors de l'appel du webhook n8n (HTTP \${response.status})\`);
  }

  return await response.json();
}`}
/>

### 4. Workflow 2 : Génération planifiée de rapport d'audit

Le second workflow fonctionne de manière autonome grâce au nœud **Schedule Trigger (Cron)** :
- **Déclenchement** : Chaque vendredi à 18h00 (`0 18 * * 5`).
- **Action 1** : Requête MySQL vers la table `documents` pour recenser les fichiers ajoutés au cours des 7 derniers jours.
- **Action 2** : Requête vers l'Interactions API de Gemini pour rédiger une synthèse analytique des thématiques abordées.
- **Action 3** : Compilation d'un rapport PDF et diffusion par email à l'équipe de direction.
