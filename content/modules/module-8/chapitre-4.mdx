### 2. Stratégies de découpage (Chunking) avec chevauchement (Overlap)

Un découpage brutal par nombre arbitraire de caractères risque de couper une phrase essentielle en plein milieu (ex. séparer une condition de son montant financier).

Pour préserver la continuité du sens :
- **Taille de fragment (*Chunk Size*)** : 500 à 700 tokens (environ 300 à 450 mots).
- **Chevauchement (*Chunk Overlap*)** : 80 à 120 tokens entre deux fragments consécutifs.
- **Respect des frontières naturelles** : Découpage préférentiel sur les doubles sauts de ligne (`\n\n`), puis les points (`. `), pour ne jamais briser un paragraphe cohérent.

### 3. Stockage dans Qdrant et couplage avec MySQL

Pour garantir une cohérence absolue entre le monde vectoriel (**Qdrant**) et le monde relationnel (**MySQL**), chaque fragment partage le **même identifiant unique (UUID v4)** :

<CodeBlock
  language="typescript"
  title="src/services/qdrantIngestion.service.ts — Synchronisation duale"
  code={`import { randomUUID } from 'crypto';
import { qdrantClient } from '../config/qdrant';
import { pool } from '../config/database';
import { ai } from '../config/gemini';

export async function indexDocumentChunk(
  documentId: number,
  chunkIndex: number,
  text: string,
  pageNumber: number,
  userId: number
) {
  // 1. Génération de l'identifiant pivot unique
  const pointId = randomUUID();

  // 2. Calcul du vecteur d'embedding 768-D avec Gemini
  const embeddingResult = await ai.models.embedContent({
    model: 'text-embedding-004',
    contents: [{ parts: [{ text }] }],
  });

  const vector = embeddingResult.embedding?.values;
  if (!vector) throw new Error("Échec de la génération vectorielle.");

  // 3. Insertion vectorielle dans Qdrant avec payload filtrable
  await qdrantClient.upsert('enterprise_knowledge', {
    points: [
      {
        id: pointId,
        vector,
        payload: {
          documentId,
          userId, // Permet le filtrage étanche par utilisateur
          pageNumber,
          chunkIndex,
        },
      },
    ],
  });

  // 4. Insertion relationnelle dans MySQL avec le même pointId
  await pool.execute(
    \`INSERT INTO document_chunks 
      (document_id, chunk_index, content, page_number, qdrant_point_id)
     VALUES (?, ?, ?, ?, ?)\`,
    [documentId, chunkIndex, text, pageNumber, pointId]
  );
}`}
/>

### 4. Gestion du cycle de vie : Suppression en cascade cohérente

Lorsqu'un utilisateur supprime un document depuis l'interface React :
1. Le backend récupère l'ensemble des `qdrant_point_id` associés dans la table `document_chunks`.
2. Il émet un appel de suppression par lot vers Qdrant (`qdrantClient.delete(collection, { points: [...] })`).
3. Il supprime la ligne dans MySQL (`DELETE FROM documents WHERE id = ? AND user_id = ?`).

Ce protocole élimine tout vecteur fantôme dans la base Qdrant.
