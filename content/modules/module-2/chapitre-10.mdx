# Chapitre 10 — Sécurité et Tests Frontend pour l'IA

Félicitations ! Vous avez appris à construire des interfaces complètes, réactives et performantes avec React et Gemini.

Mais avant de mettre votre application en ligne pour le grand public, il reste une étape indispensable pour tout développeur professionnel : **la sécurité et la fiabilité**.

Une IA produit du texte imprévisible : que se passe-t-il si un texte contient un script malveillant (attaque XSS) ?  
Et comment tester son application sans dépenser 10 € de crédits Google à chaque fois qu'on lance la commande de test ?  
Dans ce chapitre final du Module 2, nous allons blinder notre interface et créer des tests automatisés ultra-rapides.

---

### 1. Le danger du texte non filtré : L'attaque XSS indirecte

Imaginez qu'un utilisateur farceur (ou malveillant) demande à Gemini :  
> *"Génère un exemple de code avec la balise `<script>alert('Piraté !')</script>`"*.

Si votre application React injecte bêtement ce texte dans la page en faisant par exemple `dangerouslySetInnerHTML`, le script va s'exécuter dans le navigateur de vos visiteurs, pouvant voler leurs cookies de connexion ou leurs mots de passe !

<Callout type="warning" title="La règle d'or absolue">
**N'utilisez JAMAIS `dangerouslySetInnerHTML` avec les réponses d'une IA.**  
Utilisez toujours un afficheur de Markdown sécurisé (comme `react-markdown` couplé à `DOMPurify` ou `rehype-sanitize`) qui nettoie automatiquement le code HTML et désactive les scripts dangereux.
</Callout>

### 3. La validation humaine obligatoire (Human-in-the-Loop)

Une règle fondamentale en ingénierie de l'IA :  
**L'IA ne doit JAMAIS avoir les pleins pouvoirs d'exécuter seule une action destructrice ou financière.**

Si l'utilisateur demande : *"Supprime tous mes anciens e-mails de 2023"*, ou *"Transfère 500 € à mon collègue"*, l'IA doit simplement formuler la proposition, mais **c'est un être humain qui doit obligatoirement cliquer sur un bouton de confirmation** :

<CodeBlock language="tsx" filename="src/components/AI/ActionConfirmationModal.tsx">
{`import React from 'react';

interface Props {
  actionDescription: string;
  onConfirm: () => void;
  onCancel: () => void;
}

export const ActionConfirmationModal: React.FC<Props> = ({ actionDescription, onConfirm, onCancel }) => {
  return (
    <div className="fixed inset-0 bg-slate-900/60 backdrop-blur-xs flex items-center justify-center p-4 z-50">
      <div className="bg-white rounded-2xl max-w-md w-full p-6 shadow-xl space-y-4">
        <h3 className="text-lg font-bold text-slate-900">⚠️ Confirmation requise</h3>
        <p className="text-sm text-slate-600 leading-relaxed">
          L'assistant IA suggère d'exécuter l'action suivante :
        </p>

        {/* Encadré d'avertissement */}
        <div className="rounded-xl border border-amber-200 bg-amber-50 p-3 text-sm font-semibold text-amber-900">
          {actionDescription}
        </div>

        <div className="flex justify-end gap-3 pt-2">
          <button
            onClick={onCancel}
            className="rounded-xl border border-slate-200 px-4 py-2 text-sm font-semibold text-slate-700 hover:bg-slate-50 transition"
          >

          <button

          >
            Confirmer et exécuter
          </button>
        </div>
      </div>
    </div>
  );
};`}
</CodeBlock>

### 5. Tester son interface avec Vitest sans dépenser un centime !

Quand vous écrivez des tests automatisés, vous ne devez **JAMAIS appeler la vraie API Google Gemini**.  
Pourquoi ?
1. Vos tests seraient lents (1 à 3 secondes par test au lieu de 5 millisecondes).
2. Si votre connexion Internet coupe, vos tests échoueraient alors que votre code est bon.
3. Chaque test consommerait votre quota de tokens payants !

La solution professionnelle : **les Mocks (les doublures cascadeurs)** !  
On remplace temporairement la fonction `fetch` par un faux comédien qui répond immédiatement une fausse réponse prédéfinie.

<CodeBlock language="tsx" filename="tests/Home.test.tsx">
{`import { describe, it, expect, vi } from 'vitest';
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Home from '../src/pages/Home';
import * as aiService from '../src/services/ai.service';

describe('Composant d\'accueil Assistant IA', () => {
  it('affiche la réponse quand la génération réussit (sans appel réseau réel)', async () => {
    const user = userEvent.setup();

    // 🎭 On crée notre doublure : elle renvoie instantanément cette phrase
    vi.spyOn(aiService, 'generateText').mockResolvedValueOnce({
      success: true,
      result: 'Bonjour ! Je suis une réponse simulée en test unitaire.',
    });

    // 1. On dessine le composant en mémoire
    render(<Home />);

    const input = screen.getByPlaceholderText(/votre besoin/i);
    const submitBtn = screen.getByRole('button', { name: /générer/i });

    // 2. On simule la frappe de l'utilisateur
    await user.type(input, 'Explique TypeScript');

    // 3. On clique sur le bouton
    await user.click(submitBtn);

    // 4. On vérifie que la phrase simulée apparaît bien à l'écran !
    expect(await screen.findByText('Bonjour ! Je suis une réponse simulée en test unitaire.')).toBeInTheDocument();
  });
});`}
</CodeBlock>

Ce test s'exécute en **0,05 seconde**, ne coûte aucun centime, et prouve à 100% que votre composant React fonctionne à la perfection !
