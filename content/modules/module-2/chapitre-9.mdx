# Chapitre 9 — Performance Frontend et Optimisation de l'IA

Quand votre application de Chat n'a que 2 messages, tout va vite.  
Mais imaginez une conversation professionnelle qui dure depuis 45 minutes :
- Le fil de discussion contient désormais plus de 150 bulles.
- Le flux de streaming fait clignoter et recalculer l'écran 30 fois par seconde.
- L'ordinateur de l'utilisateur commence à chauffer et le défilement se met à saccader.

Dans ce chapitre, nous allons apprendre les **astuces indispensables des ingénieurs seniors** pour garder votre application React légère comme une plume, même avec des milliers de messages et des flux en temps réel intenses.

---

### 1. Pourquoi le streaming peut-il ralentir React ?

Chaque fois que vous modifiez un état (`setMessages(...)`), React recalcule votre composant et ses enfants.  
Pendant un flux de streaming, Google peut vous envoyer 20 à 40 petits fragments de texte par seconde !

Si votre composant est mal optimisé, React va tenter de recalculer **toutes les 150 anciennes bulles** 30 fois par seconde, ce qui consomme inutilement le processeur et la batterie du smartphone de votre utilisateur.

Voici les 3 leviers pour éviter ce piège :
1. **Mémoïser les anciens messages avec `React.memo`** : seuls les nouveaux mots qui arrivent doivent être dessinés.
2. **Le Debouncing** : attendre que l'utilisateur ait fini de taper avant de lancer une recherche IA automatique.
3. **L'interruption nette** : annuler les anciennes requêtes si l'utilisateur change d'avis.

---

### 2. Le secret de la fluidité : `React.memo` sur les bulles de messages

En enveloppant votre composant `Message` avec `React.memo`, vous dites à React :  
*"Si le texte de cette bulle n'a pas changé, ne perds pas de temps à la recalculer !"*

<CodeBlock language="tsx" filename="src/components/Chat/MemoizedMessage.tsx">
{`import React from 'react';
import type { ChatMessage } from '../../types/chat.types';

// Enveloppé dans React.memo : React ne recalculera cette bulle
// QUE si ses propriétés changent réellement !
export const MemoizedMessage = React.memo<{ message: ChatMessage }>(({ message }) => {
  const isUser = message.role === 'user';

  return (
    <div className={\`flex w-full \${isUser ? 'justify-end' : 'justify-start'} my-2\`}>
      <div className={\`max-w-[80%] rounded-2xl p-3 text-sm \${
        isUser ? 'bg-indigo-600 text-white' : 'bg-white border text-slate-800'
      }\`}>
        <p className="whitespace-pre-wrap">{message.content}</p>
      </div>
    </div>
  );
});

MemoizedMessage.displayName = 'MemoizedMessage';`}
</CodeBlock>

Grâce à cette seule ligne, pendant que le dernier message de Gemini se construit mot à mot, toutes les 149 bulles précédentes restent parfaitement figées et ne consomment quasiment aucun cycle processeur !

### 3. Le Debouncing : Éviter de harceler les serveurs

Imaginez une barre de recherche intelligente assistée par l'IA.  
Si vous lancez un appel à Gemini à **chaque lettre tapée** sur le clavier :
- Quand l'utilisateur tape le mot *"informatique"*, vous déclenchez 12 appels d'IA en 2 secondes !
- Vous gaspillez des centaines de tokens pour des mots incomplets comme *"in"*, *"info"*, *"infor"*.

Le **Debounce** (le délai de temporisation) résout ce problème avec élégance :  
On attend que l'utilisateur arrête de taper pendant au moins 400 millisecondes avant de lancer la requête !

<CodeBlock language="typescript">
{`import { useState, useEffect } from 'react';

/**
 * Hook personnalisé qui retarde la prise en compte d'une valeur
 */
export function useDebounce<T>(value: T, delayMs: number = 400): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);

  useEffect(() => {
    // On programme un compte à rebours
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delayMs);

    // Si l'utilisateur tape une nouvelle lettre avant la fin du délai,
    // on annule le compte à rebours précédent et on repart à zéro !
    return () => clearTimeout(timer);
  }, [value, delayMs]);

  return debouncedValue;
}`}
</CodeBlock>

### 4. Gérer les listes géantes : La virtualisation

Si votre application conserve des historiques de plusieurs centaines de messages, le navigateur peut saturer en créant des milliers d'éléments HTML dans le DOM.

La solution professionnelle s'appelle la **virtualisation de liste** (utilisée notamment par Twitter, Facebook ou Slack) :
- Même s'il y a 1 000 messages dans l'historique, le navigateur n'affiche que les **15 messages visibles sur votre écran**.
- Dès que vous faites défiler la page vers le haut, il retire les messages du bas et affiche ceux du haut instantanément !

Dans l'écosystème React moderne, on utilise des outils très légers comme `@tanstack/react-virtual`.
