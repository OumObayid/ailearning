# Chapitre 2 — Préparer l'environnement Frontend et le relier au Backend

Dans le premier chapitre, nous avons compris le rôle du frontend.  
Nous allons maintenant mettre les mains dans le code ! Dans ce chapitre, nous allons créer notre application React avec **TypeScript**, bien ranger nos fichiers, et fabriquer un petit service propre qui appelle notre serveur Node.js du Module 1.

Pas de panique si vous débutez avec React ou les appels réseau : chaque concept sera expliqué avec des images simples du quotidien.

---

### 1. Créer son projet React avec Vite en 30 secondes

Pour créer un projet React moderne aujourd'hui, les développeurs n'utilisent plus l'ancien *Create React App* (qui était lourd et lent).  
On utilise **Vite** : un outil ultra-rapide qui prépare votre projet en un clin d'œil.

Ouvrez votre terminal et tapez ces quelques commandes :

```bash
# 1. Créer le projet avec React et TypeScript
npm create vite@latest frontend-ia -- --template react-ts

# 2. Entrer dans le dossier
cd frontend-ia

# 3. Télécharger les outils nécessaires
npm install

# 4. Lancer le serveur local pour voir le résultat sur son écran
npm run dev
```

Vite vous affiche une adresse (par exemple `http://localhost:5173`). Ouvrez-la dans votre navigateur : votre application React fonctionne déjà !

### 2. Organiser son projet : la méthode des tiroirs bien rangés

Pour que votre projet reste facile à comprendre et agréable à travailler au fil des semaines, nous séparons les rôles dans des dossiers précis :

```text
frontend-ia/
├── src/
│   ├── components/       (Les éléments visuels réutilisables)
│   │   ├── Chat/         (La fenêtre de discussion et ses bulles)
│   │   ├── AI/           (Les animations de chargement et bandeaux d'alerte)
│   │   └── Layout/       (La barre du haut et le cadre de la page)
│   │
│   ├── services/         (Le messager : celui qui envoie les requêtes au serveur)
│   │   └── ai.service.ts
│   │
│   ├── types/            (Le dictionnaire : décrit la forme exacte des données)
│   │   └── ai.types.ts
│   │
│   ├── pages/            (Les écrans complets de l'application)
│   │   └── Home.tsx
│   │
│   ├── App.tsx           (Le composant racine)
│   └── main.tsx          (Le point de départ qui allume React)
│
├── .env                  (L'adresse de votre serveur backend)
└── package.json
```

Pourquoi cette organisation est-elle rassurante ?  
Parce que si un jour vous voulez changer la couleur d'un bouton, vous savez exactement qu'il faut ouvrir le dossier `components/`. Et si vous devez changer l'adresse de votre serveur, vous ouvrez simplement le dossier `services/` ou le fichier `.env` !

---

### 3. Configurer l'adresse du serveur backend

Dans le dossier de votre frontend, créez un fichier nommé `.env` :

```bash
# L'adresse de notre serveur Node.js créé au Module 1
VITE_API_BASE_URL=http://localhost:3000/api
```

<Callout type="note" title="Pourquoi le préfixe VITE_ ?">
Dans les projets Vite, toute variable qui commence par `VITE_` est automatiquement rendue accessible dans votre code React via `import.meta.env.VITE_API_BASE_URL`.  
Comme ces variables sont publiques, rappelez-vous : **uniquement des adresses de serveurs, jamais de clés secrètes !**
</Callout>

### 4. Le messager : Créer un service d'API propre

Au lieu de faire des requêtes `fetch()` éparpillées au hasard dans vos boutons React, nous créons un petit fichier spécialisé : `src/services/ai.service.ts`.  
C'est notre coursier dédié aux échanges avec le serveur backend :

<CodeBlock language="typescript" filename="src/services/ai.service.ts">
{`// 1. On lit l'adresse de notre backend depuis les variables d'environnement
const API_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:3000/api';

/**
 * Envoie une question à notre serveur backend et attend la réponse de Gemini
 */
export async function generateText(prompt: string) {
  // On envoie le message via la fonction fetch standard du navigateur
  const response = await fetch(\`\${API_URL}/generate\`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ prompt }),
  });

  // Si le serveur nous répond avec une erreur (ex: code 400 ou 500)
  if (!response.ok) {
    const errorBody = await response.json().catch(() => ({}));
    throw new Error(errorBody.message || \`Erreur du serveur (code \${response.status})\`);
  }

  // Tout s'est bien passé : on renvoie les données décodées
  return response.json();
}`}
</CodeBlock>

### 5. Décrire ses données avec TypeScript

Pour que notre code soit sûr et que l'éditeur (VS Code) nous aide à autocompléter chaque propriété sans faute d'orthographe, nous décrivons la forme attendue dans `src/types/ai.types.ts` :

<CodeBlock language="typescript" filename="src/types/ai.types.ts">
{`export interface GenerateResponse {
  success: boolean;       // Est-ce que tout s'est bien passé ? (true ou false)
  result: string;         // Le texte rédigé par Gemini
  tokensCount?: number;   // Optionnel : nombre de tokens consommés
  message?: string;       // Optionnel : message explicatif si besoin
}`}
</CodeBlock>

### 6. Créer notre premier composant React complet

Créons la page d'accueil dans `src/pages/Home.tsx`.  
Ce composant va écouter ce que tape l'utilisateur, appeler notre coursier `generateText`, et afficher le résultat ou les erreurs de façon élégante :

<CodeBlock language="tsx" filename="src/pages/Home.tsx">
{`import React, { useState } from 'react';
import { generateText } from '../services/ai.service';
import type { GenerateResponse } from '../types/ai.types';

export default function Home() {
  // 1. La boîte à souvenirs (les états de notre écran)
  const [prompt, setPrompt] = useState('');
  const [result, setResult] = useState('');
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState('');

  // 2. La fonction déclenchée quand l'utilisateur clique sur le bouton
  async function handleGenerate() {
    // Si le champ est vide ou qu'une génération est déjà en cours, on ne fait rien
    if (!prompt.trim() || loading) return;

    try {
      setLoading(true); // On allume le voyant "chargement"
      setError('');     // On efface les anciennes erreurs
      setResult('');    // On nettoie l'ancien texte

      // Appel de notre service (qui appelle Express, qui appelle Gemini)
      const data: GenerateResponse = await generateText(prompt.trim());
      setResult(data.result);
    } catch (err) {
      // Si la connexion coupe ou si le serveur renvoie une erreur
      setError(err instanceof Error ? err.message : 'Une erreur inattendue est survenue.');
    } finally {
      // Dans tous les cas (succès ou erreur), on éteint le voyant "chargement"
      setLoading(false);
    }
  }

  return (
    <main className="max-w-2xl mx-auto p-6 space-y-5 font-sans">
      <h1 className="text-2xl font-bold text-slate-900">
        Mon Premier Assistant IA avec React
      </h1>

      {/* Zone de saisie du texte */}
      <textarea
        rows={4}
        value={prompt}
        onChange={(e) => setPrompt(e.target.value)}
        disabled={loading}
        placeholder="Posez votre question ou décrivez votre besoin..."
        className="w-full rounded-xl border border-slate-300 p-3 text-sm focus:border-indigo-500 focus:outline-none"
      />

      {/* Barre d'action avec compteur et bouton */}
      <div className="flex items-center justify-between">
        <span className="text-sm text-slate-500">
          {prompt.length} / 500 caractères
        </span>
        <button
          onClick={handleGenerate}
          disabled={loading || !prompt.trim() || prompt.length > 500}
          className="rounded-xl bg-indigo-600 px-5 py-2.5 text-sm font-semibold text-white hover:bg-indigo-700 disabled:opacity-50 transition"
        >
          {loading ? 'L\'IA réfléchit...' : 'Générer la réponse'}
        </button>
      </div>

      {/* Affichage d'un message d'erreur si besoin */}
      {error && (
        <div className="rounded-xl border border-rose-200 bg-rose-50 p-4 text-sm text-rose-800">
          ⚠️ {error}
        </div>
      )}

      {/* Affichage de la réponse réussie */}
      {result && (
        <div className="rounded-xl border border-slate-200 bg-white p-5 shadow-sm text-sm text-slate-800 whitespace-pre-wrap leading-relaxed">
          <div className="text-xs font-bold text-indigo-600 uppercase mb-2">
            Réponse de Gemini :
          </div>
          {result}
        </div>
      )}
    </main>
  );
}`}
</CodeBlock>

### 7. Comprendre l'asynchronisme : L'analogie du biper de restaurant

Pourquoi avons-nous écrit `async` et `await` dans notre fonction ?

Imaginez que vous commandiez un burger au restaurant :
- Si le système était **synchrone (bloquant)** : vous resteriez debout devant le caissier sans bouger pendant 5 minutes, personne d'autre ne pourrait commander, et vous n'auriez même pas le droit de cligner des yeux !
- Avec le système **asynchrone (`async / await`)** : le caissier vous donne un petit boîtier électronique qui sonnera quand le burger sera prêt (`await`). Pendant ce temps, vous allez vous asseoir, vous discutez avec vos amis, et l'écran de votre téléphone reste totalement fluide et réactif !

C'est exactement ce que fait React : pendant que Google réfléchit, votre site ne se fige pas. L'utilisateur peut encore scroller, cliquer ou lire d'autres articles.
