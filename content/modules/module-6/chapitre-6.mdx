# Chapitre 6 — Gestion de l'état, mémoires court/long terme et persistance relationnelle

### 1. Définition et typage de l'AgentState

Dans toute application agentique professionnelle, **l'état (*State*)** désigne la structure de données centrale qui consigne l'ensemble des informations nécessaires à la réalisation de la tâche au fur et à mesure de son avancement.

### 2. Différence fondamentale entre état éphémère et mémoire durable

Il ne faut jamais confondre l'**état de travail** et la **mémoire** :

| Notion | Portée temporelle | Rôle technique | Support de stockage |
| :--- | :--- | :--- | :--- |
| **État courant (*State*)** | Durée d'une seule exécution | Mémoriser les calculs intermédiaires, le nombre de pas et les sorties d'outils | Mémoire vive (RAM) du processus ou checkpoint |
| **Mémoire à court terme** | Session utilisateur (quelques minutes/heures) | Suivre le fil d'une conversation (`"Rembourse-la"`, où `"la"` réfère à la commande précédente) | Cache Redis ou table de session |
| **Mémoire à long terme** | Semaines, mois ou années | Préférences client, historique des incidents résolus, documentation d'entreprise | **MySQL** (relationnel) & **Qdrant** (vectoriel) |

### 4. Schéma MySQL pour l'historique conversationnel de l'agent

Pour permettre à votre agent de se souvenir des requêtes passées tout en préservant l'intégrité relationnelle, déployez les deux tables suivantes dans MySQL :

<CodeBlock
  language="sql"
  title="Schéma DDL des tables de mémoire agentique (MySQL)"
  code={`-- 1. Table des fils de conversation
CREATE TABLE IF NOT EXISTS agent_conversations (
  id VARCHAR(64) PRIMARY KEY,
  user_id INT NOT NULL,
  title VARCHAR(255) NOT NULL DEFAULT 'Nouvelle session',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_conversations (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 2. Table des messages et traces d'outils
CREATE TABLE IF NOT EXISTS agent_messages (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  conversation_id VARCHAR(64) NOT NULL,
  role ENUM('user', 'assistant', 'system', 'tool_call', 'tool_result') NOT NULL,
  content TEXT NOT NULL,
  tool_name VARCHAR(64) NULL,
  metadata JSON NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (conversation_id) 
    REFERENCES agent_conversations(id) 
    ON DELETE CASCADE,
  INDEX idx_conversation_lookup (conversation_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;`}
/>

<Callout type="danger" title="Cloisonnement strict par utilisateur">
Lors de la récupération de l&apos;historique conversationnel, vérifiez systématiquement que la conversation appartient bien au <code>user_id</code> issu du jeton d&apos;authentification JWT de l&apos;utilisateur connecté, afin d&apos;empêcher toute attaque de type IDOR (*Insecure Direct Object Reference*).
</Callout>
