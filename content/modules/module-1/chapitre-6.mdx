# Chapitre 6 — Obtenir des réponses structurées avec JSON et Zod

Quand vous discutez avec Gemini sur son interface web, lire de beaux paragraphes de texte en français est très agréable.  
Mais pour une **application informatique** (votre site web, votre application mobile ou votre base de données), du texte libre est un véritable cauchemar à traiter !

Comment afficher un badge vert ou rouge si l'IA écrit tantôt *"J'ai bien aimé"*, tantôt *"C'est plutôt sympa"* ou *"Expérience satisfaisante"* ?  
Comment calculer une moyenne si la note est perdue au milieu d'une phrase de 10 lignes ?

Dans ce chapitre, nous allons apprendre à transformer Gemini en un générateur de **données ultra-propres et prévisibles au format JSON**, et à vérifier ces données avec un garde du corps infaillible nommé **Zod**.

---

### 1. Pourquoi le texte libre pose-t-il problème aux programmes ?

Imaginons que vous demandiez à l'IA d'analyser un commentaire client :
> *"Le produit est génial, mais la livraison a pris 12 jours et le carton est arrivé écrasé."*

Si l'IA vous répond par un paragraphe :
> *"Le sentiment général est mitigé. D'un côté le produit plaît beaucoup, mais de l'autre la logistique a failli avec un délai excessif et un colis endommagé."*

C'est très bien écrit, mais comment votre code JavaScript peut-il extraire automatiquement :
- La note globale ?
- La liste des problèmes pour créer un ticket dans le logiciel de support ?
- L'équipe responsable (Logistique vs Produit) ?

C'est impossible sans écrire des dizaines de lignes de code fragiles.  
La solution ? **Exiger une réponse sous forme de données structurées.**

---

### 2. Le format JSON : une boîte de rangement avec des étiquettes

Le format **JSON** (*JavaScript Object Notation*) est le langage universel utilisé par tous les serveurs du monde pour échanger des informations.  
C'est comme un casier où chaque compartiment porte une étiquette précise :

<CodeBlock language="json">
{`{
  "sentiment": "MITIGE",
  "note": 6,
  "pointsPositifs": ["Qualité du produit"],
  "problemes": ["Délai de livraison de 12 jours", "Carton endommagé"],
  "serviceConcerne": "Logistique"
}`}
</CodeBlock>

Avec ce format, votre code React peut faire en une demi-ligne :
```javascript
if (data.sentiment === "MITIGE") {
  afficherAlerteJaune();
}
```
Fini les devinettes, tout devient simple et automatique !

---

### 3. Comment forcer Gemini à répondre en JSON strict ?

Le SDK officiel de Gemini possède une fonctionnalité fantastique appelée **Structured Outputs** (Sorties Structurées).  
Elle permet de dire à l'IA : *"Tu n'as pas le droit de me raconter ta vie. Tu dois obligatoirement me répondre en respectant scrupuleusement ce moule précis"*.

Voici comment décrire le "moule" (le schéma JSON) :

<CodeBlock language="typescript">
{`const reviewJsonSchema = {
  type: "object",
  properties: {
    sentiment: {
      type: "string",
      enum: ["POSITIF", "NEUTRE", "NEGATIF"] // L'IA est obligée de choisir un de ces 3 mots !
    },
    summary: {
      type: "string",
      description: "Un résumé en une seule phrase courte."
    },
    issues: {
      type: "array",
      items: { type: "string" },
      description: "La liste des problèmes signalés."
    },
    recommendations: {
      type: "array",
      items: { type: "string" },
      description: "Les actions conseillées."
    }
  },
  // On liste les champs obligatoires que l'IA ne doit JAMAIS oublier
  required: ["sentiment", "summary", "issues", "recommendations"]
};`}
</CodeBlock>

---

### 4. Envoyer la demande avec `response_format`

Une fois le moule préparé, il suffit de le passer à `ai.interactions.create` via l'option `response_format` :

<CodeBlock language="typescript">
{`const interaction = await ai.interactions.create({
  model: GEMINI_MODEL,
  input: \`
    Analyse ce commentaire d'un acheteur :
    "La montre fonctionne à merveille mais le bracelet s'est détaché au bout de 2 jours."
  \`,
  // 🎯 On force le format JSON et on donne le moule à respecter
  response_format: {
    type: "text",
    mime_type: "application/json",
    schema: reviewJsonSchema
  }
});

// interaction.output_text contient maintenant un JSON parfait !
console.log(interaction.output_text);`}
</CodeBlock>

Gemini ne vous renverra aucun mot superflu, pas de *"Voici votre résultat : "* ni de fioritures. Uniquement le JSON brut !

---

### 5. La règle de sécurité : Ne faites JAMAIS une confiance aveugle à l'IA !

Même si Gemini fait de son mieux pour respecter votre schéma, une IA reste un modèle probabiliste.  
Une panne réseau, une coupure de texte ou une hallucination rare peuvent toujours survenir.

Si votre serveur fait directement `JSON.parse()` sans vérifier les données, et qu'un champ attendu est absent ou n'est pas du bon type, votre application entière peut planter !

Pour sécuriser tout cela, nous utilisons un outil devenu le standard absolu de l'écosystème TypeScript : **Zod**.

---

### 6. Zod : Le vigile à l'entrée de votre application

Imaginez **Zod** comme un vigile très strict à l'entrée d'une boîte de nuit.  
Il inspecte les données qui sortent de Gemini, vérifie qu'elles ont bien leur "carte d'identité", que les textes sont des textes, que les notes sont des nombres, et bloque impitoyablement tout ce qui est louche.

#### Définir un schéma avec Zod :
<CodeBlock language="typescript">
{`import { z } from "zod";

// On définit les règles du jeu avec Zod
export const ReviewAnalysisSchema = z.object({
  sentiment: z.enum(["POSITIF", "NEUTRE", "NEGATIF"]),
  summary: z.string(),
  issues: z.array(z.string()),
  recommendations: z.array(z.string())
});

// Zod peut même déduire automatiquement le type TypeScript correspondant !
export type ReviewAnalysis = z.infer<typeof ReviewAnalysisSchema>;`}
</CodeBlock>

#### Valider en toute sécurité avec `safeParse()` :
Au lieu d'utiliser `.parse()` (qui déclenche une grosse erreur si quelque chose ne va pas), on utilise **`.safeParse()`** :

<CodeBlock language="typescript">
{`// 1. On transforme le texte brut en objet JavaScript
const rawObject = JSON.parse(interaction.output_text);

// 2. Le vigile Zod inspecte l'objet
const validation = ReviewAnalysisSchema.safeParse(rawObject);

if (!validation.success) {
  // Les données sont corrompues : on intercepte proprement sans faire planter le serveur
  console.error("Erreur de conformité des données :", validation.error);
  throw new Error("L'IA a produit des données non conformes.");
}

// 3. Tout est parfait : on utilise les données validées en toute sérénité !
const validData = validation.data;
console.log("Sentiment vérifié :", validData.sentiment);
console.log("Résumé certifié :", validData.summary);`}
</CodeBlock>

### 8. À ne pas confondre : Sortie Structurée vs Appel d'outils (Function Calling)

Ces deux notions sont souvent confondues par les débutants :

- **Structured Output (ce que nous venons de faire) :** C'est simplement la **mise en forme** de la réponse. L'IA rédige un document au format JSON au lieu d'un paragraphe littéraire.
- **Function Calling (Chapitre 8) :** L'IA demande à votre serveur d'**agir dans le monde réel** (par exemple : interroger la base de données SQL pour trouver le solde bancaire d'un client, ou envoyer un e-mail).

3. Validez la réponse avec `safeParse()`.

1. Testez avec un texte volontairement loufoque ou incompréhensible.
2. Vérifiez que votre code gère l'éventuelle erreur proprement, sans faire crasher votre serveur Node.js.
