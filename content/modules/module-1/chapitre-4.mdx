# Chapitre 4 — Comprendre et utiliser l'Interactions API

Dans les chapitres précédents, nous avons vu comment formuler des consignes claires et envoyer un premier texte à Gemini.  
Nous allons maintenant plonger au cœur du moteur : **l'Interactions API** du SDK officiel de Google (`@google/genai`).

Ne soyez pas intimidé par ce nom technique : nous allons voir ensemble ce que signifie une API, pourquoi Google a choisi le mot *"Interaction"*, et comment fabriquer des fonctions propres et réutilisables dans vos projets professionnels.

---

### 1. Qu'est-ce qu'une API dans la vraie vie ?

Le mot **API** (*Application Programming Interface*) peut sembler barbare. En réalité, c'est simplement une **passerelle de communication** entre deux programmes qui ne parlent pas forcément la même langue :

1. **Votre application** pose une question dans un format convenu (une requête JSON).
2. **Le réseau Internet** achemine la demande jusqu'aux serveurs de Google.
3. **Gemini** réfléchit et produit une réponse.
4. **Google** renvoie le résultat dans un colis numérique bien emballé.
5. **Votre application** ouvre le colis et affiche la réponse à vos utilisateurs.

C'est exactement comme une prise électrique murale : vous n'avez pas besoin de comprendre le fonctionnement d'une centrale nucléaire ou d'un barrage hydraulique pour brancher votre chargeur. La prise vous fournit une interface standardisée et sécurisée.

---

### 2. Pourquoi parle-t-on d'"Interactions API" ?

Historiquement, les intelligences artificielles fonctionnaient comme un simple distributeur de confiseries : on glissait une pièce (un texte) et une friandise sortait (la réponse), puis la machine oubliait tout immédiatement.

Google a introduit une approche beaucoup plus moderne appelée **Interactions API** :
- Une **Interaction** n'est pas seulement un texte jetable.
- C'est un **échange identifié** qui possède son propre numéro de dossier unique (un `id`).
- Elle peut contenir plusieurs étapes : une question, une réflexion, l'utilisation d'un outil externe (comme une calculette ou une météo), et la réponse finale.
- Elle permet de continuer facilement une conversation au tour suivant en rappelant simplement cet identifiant !

---

### 3. Anatomie d'un premier appel d'interaction

Regardons en détail comment s'écrit cet appel en TypeScript :

<CodeBlock language="typescript">
{`import { ai, GEMINI_MODEL } from "./config/gemini.js";

// On demande à Gemini d'ouvrir une nouvelle interaction
const interaction = await ai.interactions.create({
  model: GEMINI_MODEL,
  input: "Explique le fonctionnement d'une API en une seule phrase simple."
});

// On affiche le texte final répondu par l'IA
console.log("Réponse de Gemini :");
console.log(interaction.output_text);`}
</CodeBlock>

#### Que signifie chaque élément ?
- **`ai.interactions.create()`** : C'est la méthode du SDK qui compose le numéro de Google et ouvre la session de travail.
- **`model: GEMINI_MODEL`** : Vous désignez quel modèle de la famille Gemini doit répondre (par exemple `gemini-3.8-flash`).
- **`input: "..."`** : C'est le contenu que vous donnez au modèle (votre texte ou votre question).
- **`interaction.output_text`** : C'est la propriété magique qui contient le texte rédigé par l'IA.

---

### 4. Le trousseau d'options disponibles

Lorsque vous appelez `ai.interactions.create()`, vous pouvez lui passer plusieurs options pour personnaliser l'interaction selon vos besoins :

| Option | Rôle en clair | Exemple d'utilisation |
| :--- | :--- | :--- |
| **`model`** | Le cerveau choisi pour la tâche | `"gemini-3.8-flash"` |
| **`input`** | La consigne ou question utilisateur | `"Résume ce texte en 3 points."` |
| **`system_instruction`** | Les règles générales de comportement | `"Tu es un professeur de mathématiques bienveillant."` |
| **`previous_interaction_id`** | Le numéro de l'interaction précédente | Utilisé pour se souvenir de ce qu'on disait juste avant *(voir Chapitre 5)* |
| **`response_format`** | Forcer l'IA à répondre dans un format strict | `"application/json"` *(voir Chapitre 6)* |
| **`stream`** | Recevoir la réponse mot par mot en direct | Pour créer un effet d'écriture en direct *(voir Chapitre 8)* |
| **`tools`** | Donner des outils externes à l'IA | Permet à l'IA de consulter une base de données ou une météo |

---

### 5. Construire une fonction utilitaire propre et réutilisable

Dans un projet réel, vous n'allez pas réécrire `ai.interactions.create(...)` dans chaque fichier de votre serveur.  
Vous allez créer **une seule fonction helper bien propre**, que tous vos contrôleurs pourront appeler en une ligne :

<CodeBlock language="typescript" filename="src/services/gemini.service.ts">
{`import { ai, GEMINI_MODEL } from "../config/gemini.js";

// On définit les options acceptées par notre fonction
interface AskGeminiOptions {
  prompt: string;
  systemInstruction?: string; // Optionnel
  model?: string;             // Optionnel (on prendra le modèle par défaut sinon)
}

// On définit la forme propre de ce qu'on renvoie
interface AskGeminiResponse {
  id: string;                 // L'identifiant unique de l'échange
  text: string;               // Le texte produit par Gemini
  modelUsed: string;          // Le modèle qui a répondu
}

/**
 * Fonction réutilisable pour interroger Gemini en toute simplicité
 */
export async function askGemini(options: AskGeminiOptions): Promise<AskGeminiResponse> {
  const model = options.model || GEMINI_MODEL;

  const interaction = await ai.interactions.create({
    model,
    input: options.prompt,
    system_instruction: options.systemInstruction
  });

  return {
    id: interaction.id,
    text: interaction.output_text || "",
    modelUsed: model
  };
}`}
</CodeBlock>

Grâce à cette fonction, dans n'importe quel autre fichier de votre projet, interroger l'IA devient un jeu d'enfant :
```typescript
const { text } = await askGemini({ prompt: "Bonjour !" });
```

### 6. Décortiquer la réponse : que nous renvoie vraiment Google ?

Quand vous faites un `console.log(interaction)`, Google ne vous renvoie pas juste une simple chaîne de caractères. Il vous renvoie un objet riche en informations :

<CodeBlock language="typescript">
{`const interaction = await ai.interactions.create({
  model: GEMINI_MODEL,
  input: "Donne trois qualités d'un bon développeur."
});

console.log("ID de l'échange :", interaction.id);
// Exemple : "interactions/abc-123-xyz"

console.log("Texte généré :", interaction.output_text);
// "1. La curiosité, 2. La rigueur, 3. L'esprit d'équipe."

console.log("Statistiques de tokens :", interaction.usage);
// { prompt_tokens: 12, candidates_tokens: 35, total_tokens: 47 }`}
</CodeBlock>

<Callout type="warning" title="Règle d'or pour le frontend">
Ne renvoyez jamais l'objet `interaction` brut et complet à votre application React ou mobile.  
Renvoyez uniquement ce dont le visiteur a besoin (par exemple `{ success: true, text: interaction.output_text }`). Cela allège la connexion Internet et évite de divulguer des détails techniques inutiles de votre infrastructure.
</Callout>

---

### 7. Bon à savoir : `generateContent` vs `interactions`

Si vous regardez d'anciens tutoriels sur Internet ou la documentation historique de Google Gemini, vous verrez souvent cette méthode :
```typescript
ai.models.generateContent(...)
```
C'est l'ancienne interface, centrée uniquement sur un appel textuel isolé sans suivi de conversation.

Dans cette formation, nous nous concentrons sur la nouvelle **Interactions API** (`ai.interactions.create`), car c'est la norme moderne recommandée par Google pour gérer la mémoire, les agents intelligents et les appels d'outils.
