# Chapitre 5 — Gérer les conversations et la mémoire avec Gemini

Avez-vous déjà essayé de discuter avec quelqu'un qui oublie tout ce que vous venez de dire dès que vous reprenez votre souffle ? C'est frustrant, n'est-ce pas ?

C'est pourtant exactement comme cela que fonctionne une intelligence artificielle par défaut ! Chaque fois que vous lui envoyez un message, elle repart d'une feuille totalement blanche, sans aucun souvenir du passé.

Dans ce chapitre, nous allons découvrir comment donner de la mémoire à nos applications pour créer de véritables conversations fluides, comme sur ChatGPT ou WhatsApp, grâce à une fonctionnalité puissante de Gemini : le **`previous_interaction_id`**.

---

### 1. Pourquoi l'IA est-elle amnésique par défaut ?

Prenons un exemple très simple :
- **Message 1 envoyé à l'IA :** *"Je m'appelle Thomas et je prépare un marathon."*
- **Message 2 envoyé 5 secondes plus tard :** *"Quel est mon prénom ?"*

Si vous envoyez ces deux messages comme des requêtes indépendantes, l'IA vous répondra :  
> *"Je suis désolé, je ne connais pas votre prénom car vous ne me l'avez pas indiqué."*

Pourquoi cette réaction ?  
Parce que les serveurs web fonctionnent en mode **"sans état" (stateless)** : chaque requête est traitée comme si c'était la toute première fois de sa vie que le serveur vous rencontrait.

Pour qu'une conversation fonctionne, nous devons **relier le fil conducteur** entre les questions successives.

---

### 2. La solution magique de Google : `previous_interaction_id`

Pour résoudre ce problème sans vous forcer à renvoyer tout le texte de la discussion à chaque message (ce qui consommerait énormément de tokens et coûterait cher), Google utilise un système de **ticket de suivi** :

1. Lorsque vous envoyez votre premier message, Gemini vous répond et vous remet un identifiant unique (par exemple `interaction.id = "conv_abc123"`).
2. Lorsque vous posez la question suivante, vous joignez simplement ce ticket dans l'option `previous_interaction_id`.
3. Gemini retrouve instantanément le fil de la discussion dans ses serveurs et répond en connaissant tout le contexte précédent !

Regardons le code en action :

#### Étape 1 : Le premier échange
<CodeBlock language="typescript">
{`const firstInteraction = await ai.interactions.create({
  model: GEMINI_MODEL,
  input: "Je m'appelle Thomas et je développe un site web avec React."
});

console.log("Réponse 1 :", firstInteraction.output_text);
// Gemini : "Enchanté Thomas ! React est une excellente bibliothèque pour le web."

// On note précieusement le ticket de l'échange :
const ticketId = firstInteraction.id;`}
</CodeBlock>

#### Étape 2 : La question suivante qui profite de la mémoire
<CodeBlock language="typescript">
{`const secondInteraction = await ai.interactions.create({
  model: GEMINI_MODEL,
  // 🔑 Le lien magique : on rappelle l'identifiant du tour précédent !
  previous_interaction_id: ticketId,
  input: "Quel est mon prénom et quelle technologie ai-je choisie ?"
});

console.log("Réponse 2 :", secondInteraction.output_text);
// Gemini : "Tu t'appelles Thomas et tu as choisi la technologie React !"`}
</CodeBlock>

Gemini a parfaitement retenu vos informations sans que vous ayez eu besoin de recopier votre première phrase. C'est simple, élégant et très économe en bande passante.

### 4. Les trois niveaux de mémoire à bien distinguer

En ingénierie logicielle, le mot "mémoire" regroupe trois réalités différentes qu'un développeur ne doit pas confondre :

1. **L'Historique d'affichage** : C'est la liste de toutes les bulles de messages (bleues et grises) que l'utilisateur voit défiler sur son écran dans son navigateur React.
2. **L'État de la session en cours (`previous_interaction_id`)** : C'est le ticket temporaire géré par Google pendant que l'utilisateur discute sur votre site.
3. **La Mémoire permanente (Base de données MySQL)** : Si l'utilisateur ferme son navigateur et revient demain matin, le ticket temporaire ne suffit plus. Vous devez avoir sauvegardé la conversation dans votre base de données pour pouvoir la recharger plus tard.

### 5. Créer une fonction de conversation universelle

Voici comment structurer un service propre dans votre code TypeScript pour gérer aussi bien le premier message que les messages suivants :

<CodeBlock language="typescript" filename="src/services/gemini.service.ts">
{`import { ai, GEMINI_MODEL } from "../config/gemini.js";

interface ChatMessageOptions {
  message: string;
  previousInteractionId?: string; // Facultatif au tout début
}

export async function sendChatMessage(options: ChatMessageOptions) {
  // On prépare la requête vers Gemini
  const interaction = await ai.interactions.create({
    model: GEMINI_MODEL,
    input: options.message,
    // Si on a un ticket précédent, on le transmet, sinon on démarre à zéro
    ...(options.previousInteractionId
      ? { previous_interaction_id: options.previousInteractionId }
      : {})
  });

  return {
    reply: interaction.output_text,
    newInteractionId: interaction.id
  };
}`}
</CodeBlock>

### 6. Que faire quand une conversation devient gigantesque ?

Imaginez une discussion qui dure depuis 3 semaines avec plus de 200 questions.  
La mémoire de travail de l'IA (sa "fenêtre de contexte") n'est pas infinie, et faire relire 200 messages finit par ralentir le système et coûter cher en tokens.

Voici les 2 réflexes professionnels pour gérer les longues conversations :
- **Faire une synthèse automatique** : De temps en temps, on demande à Gemini : *"Résume les 20 derniers messages en 5 lignes de faits essentiels (nom du client, problème rencontré, solutions déjà tentées)"*, puis on repart sur une nouvelle session propre avec ce résumé en instruction système !
- **Purger l'historique obsolète** : Ne conserver que les 10 derniers échanges récents, ce qui est amplement suffisant pour 95 % des cas d'usage courants.
