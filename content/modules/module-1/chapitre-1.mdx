# Chapitre 1 — Comprendre les modèles de langage et Google Gemini

### 1. Qu'est-ce qu'un modèle de langage ?

Un modèle de langage (LLM, Large Language Model) est un système d'intelligence artificielle entraîné sur de grandes quantités de données afin d'apprendre les structures du langage et de produire des réponses à partir d'une entrée.

Il peut notamment :
- Comprendre des instructions formulées en langage naturel.
- Générer du texte.
- Résumer des documents.
- Extraire des informations.
- Classifier des données.
- Traduire des contenus.
- Analyser des images.
- Produire des réponses structurées.
- Utiliser des outils externes lorsqu'il en a la possibilité.

Contrairement à un programme classique, dont les instructions sont explicitement écrites par le développeur, un modèle de langage produit ses réponses à partir de mécanismes appris pendant son entraînement et de son contexte d'exécution.

#### Exemple
Une application classique peut rechercher une valeur précise dans une base de données.

Un modèle de langage peut recevoir une demande comme :
> « Analyse ces commentaires clients et indique les trois problèmes les plus fréquents. »

Il va interpréter la demande, examiner le contenu fourni et générer une synthèse.

<Callout type="warning" title="Attention">
Le modèle ne connaît pas automatiquement les données privées de ton application. Il faut lui transmettre les informations nécessaires ou lui donner accès à des outils contrôlés.
</Callout>

### 2. Qu'est-ce que Google Gemini ?

Google Gemini est une famille de modèles d'intelligence artificielle développés par Google.

Ces modèles peuvent être utilisés dans des applications pour :
- Générer du contenu.
- Analyser des informations.
- Comprendre des images et d'autres médias.
- Extraire des données.
- Répondre à des questions.
- Utiliser des fonctions et des outils.
- Participer à des workflows intelligents.

Dans cette formation, Gemini sera notre fournisseur IA principal.

Nous utiliserons le SDK officiel Google pour JavaScript et TypeScript : `@google/genai`.

---

### 3. Comprendre les tokens

Un token est une unité de texte traitée par un modèle.

Un token peut représenter :
- Un mot complet.
- Une partie d'un mot.
- Un signe de ponctuation.
- Un espace ou une unité de texte.

**Exemple :**  
Une phrase comme :  
*« Je développe une application avec React. »*  
est transformée en unités internes avant son traitement.

Le nombre de tokens ne correspond donc pas exactement au nombre de mots.

**Pourquoi est-ce important ?**  
Parce que les tokens interviennent dans :
- La capacité de contexte du modèle.
- Le volume de données envoyé.
- La consommation des ressources.
- Le calcul des coûts selon le modèle et la tarification applicable.

### 4. Comprendre la fenêtre de contexte

La fenêtre de contexte correspond à la quantité d'informations qu'un modèle peut prendre en compte dans une interaction.

Elle peut inclure :
- Les instructions système.
- La question de l'utilisateur.
- Les messages précédents.
- Les documents transmis.
- Les résultats des outils.
- Les informations supplémentaires nécessaires à la réponse.

**Exemple :**  
Un utilisateur demande :  
*« Analyse ce document. »*  
Puis :  
*« Quels sont les trois risques principaux ? »*  
Pour répondre correctement, le système doit conserver ou retrouver le document concerné.

La gestion du contexte sera donc essentielle dans les applications conversationnelles.

---

### 5. Comprendre les hallucinations

Une hallucination est une réponse produite par un modèle qui contient une information incorrecte, inventée ou insuffisamment fondée.

**Exemple :**  
Un utilisateur demande une fonction qui n'existe pas dans une bibliothèque.  
Le modèle peut proposer une méthode fictive qui semble pourtant plausible.

**Pour limiter ce risque :**
- Fournir des informations pertinentes.
- Formuler des instructions précises.
- Utiliser des sources documentaires fiables.
- Demander au modèle de signaler les incertitudes.
- Valider les réponses structurées.
- Effectuer des vérifications métier côté serveur.
- Utiliser des tests.

Une réponse bien formulée n'est pas nécessairement une réponse exacte.

### 6. Les principales catégories d'utilisation

| Catégorie | Exemple |
| :--- | :--- |
| **Génération** | Rédiger une description de produit |
| **Synthèse** | Résumer un rapport |
| **Extraction** | Extraire le nom et l'adresse d'un texte |
| **Classification** | Identifier le sentiment d'un commentaire |
| **Analyse** | Examiner des données métier |
| **Multimodal** | Décrire une image |
| **Conversation** | Répondre à plusieurs questions liées |
| **Tool calling** | Appeler une fonction externe |
