# Chapitre 4 — Déclencheurs temporels et Webhooks HTTP

### 1. Déclenchement manuel (Manual Trigger)

Le nœud **Manual Trigger** (*When clicking 'Test workflow'*) constitue l'outil indispensable du développeur lors de la phase de conception :
- Il permet d'initier l'exécution d'un simple clic depuis l'éditeur visuel.
- Il ne nécessite aucun appel réseau extérieur.
- Il permet d'injecter des jeux d'essai fictifs (*mock data*) pour valider unitairement le comportement de chaque étape aval.

En environnement de production, les déclencheurs manuels sont systématiquement désactivés au profit de déclencheurs automatiques (temporels ou événementiels).

---

### 2. Déclenchement planifié (Schedule Trigger & Cron)

Le nœud **Schedule Trigger** réveille un workflow à intervalles réguliers pour exécuter des tâches de fond récurrentes :
- Synchronisation quotidienne des stocks avec l'ERP.
- Nettoyage nocturne des sessions expirées en base de données.
- Envoi d'un récapitulatif hebdomadaire des métriques de performance sur Slack.

Il propose deux modes de configuration :
1. **Mode standard par sélecteur** : Toutes les X minutes, toutes les heures, ou un jour précis à heure fixe.
2. **Mode Cron personnalisé** : Pour une granularité totale respectant la syntaxe UNIX standard.

### 3. Le déclencheur universel Webhook Trigger

Le nœud **Webhook Trigger** est le pilier de l'architecture événementielle moderne. Il expose un point de terminaison HTTP (endpoint) sur votre instance n8n capable de recevoir des requêtes externes (`GET`, `POST`, `PUT`, `DELETE`).

#### Paramètres clés du nœud Webhook
- **HTTP Method** : Sélectionnez `POST` pour recevoir des données structurées dans le corps de la requête.
- **Path** : L'identifiant de la route (ex. `incoming-ticket` donnera `http://localhost:5678/webhook/incoming-ticket`).
- **Response Mode** :
  - *On Received* (Recommandé pour les flux asynchrones) : n8n renvoie instantanément un code `HTTP 200 OK` dès réception de la charge, puis exécute le workflow en tâche de fond.
  - *When Last Node Finishes* : La connexion HTTP reste ouverte jusqu'à ce que le dernier nœud produise un résultat (utile pour des requêtes synchrones où le client attend la réponse immédiate).

---

### 4. Différence cruciale : URL de Test versus URL de Production

L'une des erreurs les plus fréquentes lors de la mise en service d'un webhook n8n réside dans la confusion entre les deux URL générées par l'outil :

| Propriété | URL de Test (`/webhook-test/...`) | URL de Production (`/webhook/...`) |
| :--- | :--- | :--- |
| **Objectif** | Mise au point et débogage pas-à-pas | Utilisation réelle par vos applications en ligne |
| **État d'écoute** | Écoute active **uniquement** si vous avez cliqué sur *Test step* | Écoute active permanente 24h/24 |
| **Activation du flux** | Fonctionne même si le bouton *Active* du workflow est éteint | Nécessite obligatoirement que le workflow soit basculé sur **Active** |
| **Persistance des logs** | Affiché en direct dans la fenêtre de test | Consigné dans l'historique des exécutions (*Executions panel*) |

<Callout type="danger" title="Ne jamais coder l'URL de test dans vos services Node.js">
L'URL de test ne répond qu'à un seul appel à la fois lorsque vous êtes devant votre écran. Si votre serveur Express envoie des requêtes vers l'URL `/webhook-test/` en production, les requêtes échoueront avec une erreur `404 Webhook not registered`.
</Callout>

### 5. Travail pratique 2 : Créer et tester un webhook avec curl

<p className="text-sm text-slate-700 leading-relaxed">
Dans cet exercice, vous allez créer un point d'entrée HTTP sécurisé dans n8n et vérifier son bon fonctionnement à l'aide de l'utilitaire en ligne de commande <code>curl</code>.
</p>

#### Étape 1 : Configurer le Webhook dans n8n
1. Créez un nouveau workflow intitulé `TP2 - Webhook Receiver`.
2. Ajoutez un nœud **Webhook Trigger**.
3. Définissez la méthode sur **POST** et le chemin d'accès (*Path*) sur `contact-form`.
4. Basculez sur l'onglet **Test URL** et copiez l'URL fournie (ex. `http://localhost:5678/webhook-test/contact-form`).
5. Cliquez sur le bouton bleu **Listen for test event**.

#### Étape 2 : Émettre la requête curl de test
Ouvrez votre terminal et exécutez la commande suivante :

```bash
curl -X POST "http://localhost:5678/webhook-test/contact-form" \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: my_secret_token_dev_42" \
  -d '{
    "ticketId": "TCK-1001",
    "clientEmail": "dupont@client.fr",
    "subject": "Problème d authentification",
    "message": "Je ne parviens plus à me connecter à mon espace client depuis ce matin."
  }'
```

#### Étape 3 : Valider la réception
Dans n8n, le nœud Webhook passe immédiatement au vert. L'inspecteur affiche l'objet JSON complet :
- `$json.headers["x-webhook-secret"]`
- `$json.body.ticketId`
- `$json.body.message`
</PracticalWork>
