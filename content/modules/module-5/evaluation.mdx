# Chapitre 13 — Bonnes pratiques, évaluation des acquis & Annexes

### 1. Guide des bonnes pratiques professionnelles n8n

Pour garantir la maintenabilité, la performance et la sécurité de vos flux en production, appliquez scrupuleusement ces règles éprouvées :

1. **Nommez explicitement chaque nœud** : Ne laissez jamais les libellés par défaut comme `HTTP Request 1` ou `Code 2`. Préférez `Vérifier Token Secours` ou `Gemini - Classification Support`.
2. **Versionnez vos workflows** : Exportez régulièrement vos configurations JSON sous contrôle de source Git pour suivre l'historique des modifications de l'équipe.
3. **Isolez la logique métier dans des sous-workflows** : Découpez les processus de plus de 15 nœuds en sous-workflows réutilisables.
4. **Activez l'épuration automatique des exécutions** : Activez `EXECUTIONS_DATA_PRUNE=true` pour empêcher la saturation du disque serveur par les données d'exécution anciennes.
5. **Défense en profondeur pour les clés d'API** : Utilisez exclusivement le gestionnaire d'identifiants n8n et ne partagez jamais de fichiers JSON contenant des secrets en clair.

### 2. Glossaire technique de l'automatisation

| Terme | Définition précise |
| :--- | :--- |
| **Workflow** | Graphe orienté décrivant une suite ordonnée d'étapes d'automatisation. |
| **Node (Nœud)** | Bloc unitaire d'un workflow réalisant une action, un déclenchement ou un calcul. |
| **Trigger** | Événement initial qui déclenche l'exécution du workflow (Webhook, Cron, Manuel). |
| **Array of Items** | Structure interne standardisée de n8n où chaque donnée est un objet `{ json: ... }`. |
| **Idempotence** | Propriété d'une opération pouvant être exécutée plusieurs fois sans modifier le résultat au-delà de la première exécution. |
| **Human-in-the-Loop** | Patron d'architecture exigeant l'approbation explicite d'un opérateur humain avant de finaliser une action sensible. |
| **Queue Mode** | Mode distribué où Redis sert de tampon de tâches exécutées par plusieurs conteneurs n8n workers. |
