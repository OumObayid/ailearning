# Projet de synthèse — Plateforme intelligente de support client

### 1. Présentation du projet

Dans ce projet de synthèse, vous allez assembler l'ensemble des compétences acquises au cours des chapitres précédents pour concevoir et déployer une **plateforme complète de traitement intelligent des demandes d'assistance**.

Le système doit automatiser l'analyse, la classification sémantique, la détection de criticité, la persistance relationnelle et l'aiguillage multicanal des messages clients sans blocage pour l'utilisateur.

### 4. Guide d'implémentation pas-à-pas

  title="Mise en œuvre intégrale du projet de synthèse"

<p className="text-sm text-slate-700 leading-relaxed">
Suivez rigoureusement ces 4 phases pour réaliser votre plateforme d'automatisation de niveau professionnel :
</p>

#### Phase 1 : Initialisation de la persistance MySQL
Créez la base de données `support_platform` et appliquez le schéma relationnel décrit au Chapitre 6 avec les colonnes `id`, `client_email`, `subject`, `raw_message`, `ai_category`, `ai_priority`, `ai_summary` et `status`.

#### Phase 2 : Passerelle Backend Express
Implémentez la route `POST /api/tickets` en TypeScript :
- Validation Zod sur les champs `clientEmail`, `subject` et `message`.
- Insertion SQL avec statut `received`.
- Émission de la requête POST asynchrone vers l'URL n8n avec l'en-tête `X-Webhook-Secret`.
- Réponse immédiate avec le code HTTP 202 et l'ID du ticket.

#### Phase 3 : Construction du workflow n8n
Dans l'interface n8n :
1. Créez un nœud **Webhook Trigger** en méthode POST avec le chemin `/incoming-ticket`.
2. Connectez un nœud **Code** qui compare `headers['x-webhook-secret']` avec votre variable secrète.
3. Ajoutez un nœud **Google Gemini** sollicitant le modèle `gemini-2.5-flash` avec un prompt imposant le format JSON strict.
4. Reliez un nœud **Switch** routant vers 3 branches distinctes.
5. Sur chaque branche, connectez un nœud **MySQL** mettant à jour la ligne du ticket (`UPDATE support_tickets SET ai_category = ?, ai_priority = ?, status = 'processed' WHERE id = ?`).
6. Activez le workflow en production (*Active toggle*).

#### Phase 4 : Raccordement et test d'intégration
Depuis l'application React, soumettez un formulaire avec le texte :
> *« Panne totale : notre serveur de paiement rejette toutes les transactions des clients ! »*

Observez :
1. La réception instantanée de l'ID du ticket sur le navigateur.
2. L'activation du workflow dans n8n.
3. La classification en catégorie `technical_incident` avec une priorité `CRITICAL`.
4. La mise à jour de la ligne correspondante dans MySQL.
</PracticalWork>

### 5. Critères de réussite et validation finale

Pour valider ce projet de synthèse avec les standards industriels, vérifiez les points de contrôle suivants :

- [ ] **Sécurité d'accès** : Une requête adressée au webhook n8n sans en-tête `X-Webhook-Secret` ou avec un jeton incorrect est immédiatement rejetée avec une erreur 403.
- [ ] **Déterminisme du modèle** : Les réponses JSON de Gemini sont systématiquement valides sans blocs markdown parasites (`json`).
- [ ] **Absence de régression SQL** : Toutes les écritures MySQL s'effectuent via des paramètres liés (`?`), sans concaténation de variables.
- [ ] **Expérience asynchrone** : Le frontend ne subit aucun temps d'attente supérieur à 100 ms lors de la soumission du formulaire.
