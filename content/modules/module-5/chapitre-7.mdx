# Chapitre 7 — Intégrer Google Gemini dans les workflows n8n

### 1. Pourquoi injecter Gemini dans une automatisation ?

Traditionnellement, les logiciels d'automatisation étaient aveugles face au langage naturel. Dès qu'un client s'exprimait avec des expressions familières, de l'argot ou des métaphores, les filtres par expressions régulières perdaient toute efficacité.

En intégrant **Google Gemini** au sein d'un workflow n8n, nous dotons nos flux d'une couche d'intelligence cognitive capable de :
- **Classifier l'intention** sans règles rigides prédéfinies.
- **Détecter l'urgence réelle** et l'état émotionnel (sentiment positif, neutre ou frustré).
- **Extraire des entités clés** (numéro de facture, type d'appareil, date limite) à partir d'un paragraphe brut.
- **Produire un résumé synthétique** en une phrase pour faciliter la prise en charge par les équipes humaines.

---

### 2. Intégration officielle Gemini versus appel HTTP Request direct

Pour solliciter Gemini dans n8n, deux options s'offrent au développeur :

#### Option A : Les nœuds natifs n8n LangChain (@n8n/n8n-nodes-langchain)
n8n intègre une suite de sous-nœuds IA basés sur LangChain :
- Nœud racine : **Basic LLM Chain** ou **AI Agent**.
- Modèle de langage connecté : **Google Gemini Chat Model** (sélection de `gemini-2.5-flash` ou `gemini-1.5-pro`).
- Parser de sortie : **Structured Output Parser** pour contraindre la réponse à un schéma JSON typé.

#### Option B : Le nœud HTTP Request direct vers l'API Google
Cette option offre un contrôle total sans dépendance envers les abstractions LangChain. L'appel s'effectue via un simple POST :

<CodeBlock
  language="bash"

      "parts": [
        {

        }

### 3. Exemple d'analyse : Classification sémantique d'un message

Pour obtenir une réponse exploitable par un nœud informatique en aval, nous devons imposer à Gemini un contrat d'interface strict via du **Few-Shot Prompting** et une contrainte de format JSON :

<CodeBlock
  language="text"
  title="Prompt système de classification sémantique"
  code={`Tu es un classificateur de tickets d'assistance technique pour une plateforme SaaS.
Analyse le message reçu et génère UNIQUEMENT un objet JSON conforme à cette structure :

{
  "category": "technical_incident" | "billing" | "feature_request" | "spam",
  "priority": "LOW" | "NORMAL" | "HIGH" | "CRITICAL",
  "sentiment": "positive" | "neutral" | "frustrated",
  "summary": "Résumé concis de la demande en moins de 15 mots"
}

Règles de classification :
- Si le système est inaccessible ou plante en production : priority = "CRITICAL", category = "technical_incident".
- Si le message concerne une facture, un paiement ou un remboursement : category = "billing".
- Ne génère aucun texte explicatif avant ou après le JSON.

Message à classifier :
"{{ $json.userMessage }}"`}
/>

### 5. Travail pratique 4 : Aiguillage automatique de demandes de support

<p className="text-sm text-slate-700 leading-relaxed">
Dans ce TP, vous allez assembler la chaîne de traitement complète : réception d'un message, analyse par Gemini, et aiguillage vers la branche appropriée.
</p>

#### Étape 1 : Créer la clé d'API Google Gemini
1. Connectez-vous sur **Google AI Studio** (`aistudio.google.com`).
2. Générez une nouvelle clé d'API.
3. Dans n8n, créez un nouveau Credential de type **Google Gemini API** (ou **Header Auth**).

#### Étape 2 : Assembler les nœuds
1. **Webhook Trigger** : Méthode POST sur `/webhook-test/support-ai`.
2. **Google Gemini Model** : Température fixée à `0.1` pour garantir des classifications stables et déterministes.
3. **Switch Node** :
   - Règle 1 : `$json.category === 'technical_incident'`
   - Règle 2 : `$json.category === 'billing'`
   - Règle 3 : `$json.category === 'feature_request'`
4. **Sorties** : Connectez un nœud **Code** de simulation sur chaque branche pour afficher un message d'action contextuel.
</PracticalWork>
